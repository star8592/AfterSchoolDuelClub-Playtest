## 两种源模型
- R34 Pixal3D：934,492 三角面、1 个融合网格、无骨骼。输入只是 569×940 单视角立绘，面部信息不足。
- R30 参数化模型：231,201 三角面、32 网格、163 骨骼。眼镜两片单独占 63,168 面，面数分配本身也失衡。
- 两模型姿势不同，不能直接逐顶点焊接，也不能靠加面解决五官失真。

## 减面实验（同光照同视角）
原始 934492 面；中档 242967 面；低档 121483 面。
全身画面与原始模型的平均RGB差值：1.256/255、1.966/255。
面部特写差值：5.454/255、9.549/255。
证据：evidence/R36_body_LOD_3up.jpg、evidence/R36_face_LOD_3up.jpg。
这只是静态视角对比，不是动画或完整侧脸验收。

## 空间匹配
按身高对齐，R34 放大系数 2.0479 并将脚底归零。
参数化西装到 R34 表面的最近距离中位数约 4.1cm；左右琴键衣摆分别 4.8cm / 10.7cm；发型 9.9cm。
最近表面距离不等于正确的身体语义对应；不能直接整块权重转移。
见 evidence/fit-feasibility.json。

## 真实混合 GLB
candidate/R36_parametric_rig_pixal_guided_torso.glb：15,471,500 bytes，
SHA256 a77baf1ca3a4130a81815d64cbcb1fb56d4d92c6e80c39a7591957c84386b98d。
保留原参数化西装拓扑与163骨骼、1份蒙皮；新增1个上身局部 Pixal 引导形变目标。
在原参数化服装上局部修改8879个顶点，平均位移3.46mm，最大13.42mm；
0个制作好的动画片段。Blender人工骨骼姿态驱动测试成功，但不等于动画/穿插验收。
桌面与手机尺寸浏览器测试通过：实际GLB载入、滑杆修改形变目标、肩部旋转控件。
滑杆前后视觉差异极细微：桌面单帧平均 RGB 差异约0.307/255。
这只是证明骨骼和图生形状可以协同的实验，**没有改善脸，也不符合最终原画质量**。

## 下一步工程路线
1. 使用163骨骼参数化人体作为可动画底模，重新设计五官的高质量规整四边面拓扑，采用同一人物正/侧/45度面部原画校正眼、鼻、口、下巴和表情。
2. 用R34高模做服装、头发、琴键长衣摆的造型参照：逐部件重拓扑，不能直接把当前单块93万面模型当可动画底模。
3. 在衣领、袖口、腰带等隐蔽结构处对接；对重合良好部件使用 Shrinkwrap/Surface Deform，按部件的实际对应关系使用 Data Transfer 迁移骨骼权重，并添加姿态修正 Shape Keys。
4. 将原始高模的外观细节烘焙成 UV 贴图与法线/AO/PBR，分配真实可用LOD。近景主角可先试150–250k面，召唤单位必须按同屏数量与WebGPU/WebGL2真实测量再决定。
5. 最终验收包含正侧背原画一致性、关节和衣摆无穿插、独立头面表情、技能动作、真实浏览器交互、版权和许可证审查。
