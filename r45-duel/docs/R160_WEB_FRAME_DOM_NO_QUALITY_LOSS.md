# R160 · Web 战斗 HUD 零画质损失的 DOM 重复写入优化

2026-11-18；独立 QA-only 研究 PR，正式 R147 原样保留。

## 修改内容

在 `scene.mjs` 对每帧相同的 `#impact.hidden/textContent` 与英雄人像框的 `hidden / CSS left top width height / data-side / caption` 写入增加相等判断。当且仅当 `?qa=1&r160FrameCache=on` 显式开启时才跳过重复写入。无 QA 或 `off` 保留原来代码的每帧赋值语义。

不修改任何模型、网格、纹理、材质、动画、神态、战斗、音效和主/次相机；不降低 DPR、不省掉绘制帧。统计接口 `__r45SceneQA.r160DOMCache` 暴露精确跳过次数。

曾测试观众骨骼临时四元数分配路径，但真实 R147 观众没有触发这些路径，因此相关无效优化已移除，避免无收益代码堆积。

## Chrome/Vulkan 真实游戏 A/B

Z890，1280×720 桌面 CPU 限速×2 和 430×900 DPR2 手机视口 CPU 限速×3，均运行16个真实模型、60张卡牌、主角举牌和T01/E03真实双角色战斗。通过 DOM MutationObserver 监测同一 iframe 的命中提示、人像框、文字说明，再测 rAF 间隔。所有素材保持 R147 原样。

桌面逆序（优化先测 → 原版）：
- 命中提示 DOM 变更 **770→0**；人像框 **390→7**；说明文字 **60→1**。
- 优化跳过 **1596 次重复 DOM 属性写入**，0 JS/HTTP错误，所有角色和战斗 QA通过。
- 抽样显示 draw calls 仍约929，举牌阶段p95两组均约33.4ms：**不宣称帧率稳定上升**。

模拟手机正序（原版先测 → 优化）：
- 命中提示 **770→0**；人像框 **390→7**；说明文字 **52→1**；
- 优化跳过 **1500 次重复写入**。
- 举牌p95正序基线约49.9ms、优化约33.4ms；反序优化约33.4ms、基线约50.0ms。两种顺序一致，初步支持减少主线程UI写入缓解手机模拟长帧，但它仍不是中低端真机FPS或整体帧率保证。

手机模拟反序（优化先测 → 基线）：
- 优化跳过 **1512 次重复写入**，基线0；
- 命中提示 770→0，人像框390→7，说明文字48→1；
- 举牌阶段p95基线50.0ms→优化33.4ms；draw calls两种模式均约927，场景美术及渲染路径均相同。
- 当前数据表明UI层消除无效DOM写入有潜在长帧价值，但仍需真实中低配手机以及Chrome CPU profile证实收益来源。

实测同一时段的最终HUD文字：`攻击命中` 与 `我方 · 举牌特写` 两模式完全一致。画质/角色动作没有变化。原始测试 JSON 与截图：`qa/evidence/r160-frame-dom/`；浏览器测试脚本：`qa/browser-r160-frame-allocations-ab.mjs`.
