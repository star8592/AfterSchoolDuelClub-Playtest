# R164｜把碍事的大头像搬进真正的体育馆直播屏

日期 2026-11-18。项目《放学后决斗社》**Web 版**（不是失败的 Unreal 重构）。状态：QA 实验分支，尚未合并/上线。

## 玩家需求 / 不可回退的质量标准

打出魔法最重要的是看清**对手怎样被打、对手怎样反应**。R124/R145 原有前景 3D 人像 inset 会遮住主竞技场，必须从玩家画面上移除，而不能为了漂亮的“特写”挡住被命中的人、计分牌或卡牌。

替代方案：在真实 3D 体育馆内安置带悬挂结构的赛事直播屏。它不是 HTML 浮动弹层，也不是另一块覆盖游戏的 Picture-in-Picture。

- **待机**：学校赛事识别、直播待机界面；
- **出牌**：真实 VRM 决斗者摄影机 + R109 原始精致卡牌插画与名称；
- **命中**：优先转播被命中一方（红/蓝方）真实 3D 反应，不挪动主竞技场镜头；
- **结束**：大屏恢复待机，停止离屏相机渲染；
- 普通比赛所有模型、材质、动画、音效和完整魔法保持原始 R147；无降分辨率、无特效删减。

## 场馆和移动端安全布局

位置是场景空间中真实的 3D 物件，带电视金属边框、吊杆和屏幕材质：
- 横屏：(x=7.80,y=2.72,z=-6.35)，大小 4.10×2.306，位于远端看台右上；
- 竖屏：(x=4.65,y=4.96,z=-4.00)，大小 3.92×2.205；
- 背靠悬挂式结构，外侧屋顶桁架连接，**不是跟着镜头走的 UI**；
- 三维世界坐标均处于中央记分牌右边，具体屏幕包围范围不与 scoreboard 中央 x∈[-2.6,+2.6] 区域相交；
- QA 投影校核：横屏右侧NDC x≈.84，竖屏右侧≈.94，均在可见画面内；窄屏上屏幕没有被顶部操作栏截断。人物上半身与卡牌插画同屏，不干扰场上真实命中反馈。

## 画面与性能保障

- 电视摄影机只渲染相应决斗者所在 Layer 1，主竞技场维持 Layer 0 原相机。
- 复用已有 3D 人物的真实网格、材质、表情、动作，不作低精度替身。
- R109 卡牌高清画仅在需要时通过原资产路径加载；空闲画面没有第二摄像机渲染。
- 960×540 WebGLRenderTarget，桌面更新间隔 ≥55 ms、手机更新间隔 ≥83 ms（约18/12 fps的**最高**刷新频率，并非实际稳态保证）；魔法命中和画面之外的正常帧不重复创建图片和场景。
- 电视相机曝光仅在离屏拍摄期间调整，随即恢复原 1.15，主体育馆完整光效不动。
- 离屏摄像机捕获前保存并恢复 renderer render target、viewport、scissor、autoClear、shadowMap 状态；屏幕不参与摄像机自身的 Layer 1 渲染，避免屏幕递归反馈。
- 实测捕获CPU时长独立记录 p50/p95、绘制调用、视频帧数、卡牌插画加载状态，用于识别新屏幕是否导致卡顿。

## 安全/回退与其他性能研究隔离

- 仅 `?qa=1&r164Broadcast=on` 启用，不允许单独用户参数绕过 QA 开关。
- R164 `off` 或非 QA 使用原版全部行为与原始前景人像，不动正式 R147。
- 不混入有损的 R154 DPR 或 R156 法线贴图缩小；本分支独立于 R158 的加载顺序和 R161 的场馆批处理。
- 任何严重卡顿、设备不兼容、计分牌遮挡或者头部裁切都必须保持 Draft、禁止直接部署。
- 所有验证先在 Z890 本地回环服务器 `127.0.0.1:18664` 运行，不把测试服务暴露公网。

## 出牌 / 命中性能 A/B（真实运行，模拟 CPU 限速）

Chrome本地同源服务器和16个原始模型，桌面CPU×2，手机竖屏视口CPU×3；页面 rAF 帧时间+浏览器长任务。每组采样42帧闲置、70帧出牌、70帧命中。桌面正序off→on与竖屏正反序均已实际执行。

| 场景 | 原始浮动人像 off p95 | 体育馆直播 on p95 | 结论 |
|---|---:|---:|---|
| 桌面出牌 | 33.4 ms | 33.4 ms | 没有明确慢帧回归 |
| 桌面命中 | 33.4 ms | 33.4 ms | 没有明确慢帧回归 |
| 手机模拟出牌（on先行） | 50.0 ms | 33.4 ms | 有改善迹象，但受预热影响 |
| 手机模拟命中（on先行） | 33.4 ms | **50.0 ms** | 有回归风险 |
| 手机模拟出牌（off先行） | 50.1 ms | 49.9 ms | 接近 |
| 手机模拟命中（off先行） | 33.4 ms | **50.1 ms** | **逆序证实回归风险** |

新电视模式本地相机CPU渲染提交p50约桌面2.7ms、手机模拟3.2–3.5ms，额外128draw calls每次截帧；横屏最高18fps，竖屏最高12fps。**不要把网速、帧时间或画质的局部比较写成“全面优化”。** 原版进入魔法也有数百毫秒的首发Shader长任务，R164并未修复；优先另行解决R163魔法Shader首次编译。

尝试过 `requestIdleCallback` 离屏直播调度；实际在手机模拟中出现某些拍摄耗时90ms以上，且未稳定改善受击长帧，因此**拒绝该改法、从源码撤销**。保留原始对照 JSON 作为被否决的实验，不把它放入默认行为。

原始详细证据位于 `qa/evidence/r164-broadcast/r164-perf-*.json`。

## 最终决策

**R164 的“视觉与玩法”实验已经通过，性能发布门槛没有通过：维持 Draft、不合并、不上线。** 真正低端Android手机也尚未实测。

只有解决命中直播额外渲染负载，并且在手机真机中维持主画面击中反馈无卡顿、用户确认TV摆放后，才能考虑设为默认。绝不能为了性能降低人物细节、减少魔法视觉内容或者直接砍掉大屏受击镜头。
