# R180｜体育馆静态合批与全镜头安全验收

2026-11-18，《放学后决斗社》。**独立 QA / Draft / NO-GO，不修改玩家 R147，不合并 main。**

## 这轮做了什么

- 新建 scene/stadium-static-batcher.mjs。将同父节点、同原生 PBR 材质、相同顶点属性与索引结构、相同阴影行为的实体静态网格合批。保留真实顶点、UV、法线、材质和三角面。场馆观众、真实16人物、两个主人公的蒙皮骨骼、座椅 InstancedMesh 和动态记分屏绝不合并。
- QA 参数 qa=1&r180StadiumBatch=on 才生效；默认正式玩家完全关闭。25个体育馆顶灯和5个高窗复用原本数值完全一致的 PBR 材质，仅在 QA 生效。
- 初版错误地把正面看台/前墙与永远可见的建筑合并，存在转到背面时遮挡风险。已检查原本的相机遮挡规则并改成 always、front-120、front-sign-100、side-wall 独立可见性组。背面看台与原侧墙规则保留。
- 真实合并结构：148个源静态网格 → 19个组，名义减少129个绘制路径，11,648个原三角面全部保留，merge失败数0；真实节省的 GPU 绘制次数视相机剔除与阴影处理而变。

## 两名决斗主角：未冒险处理原骨骼

只读真实 VRM/SkinnedMesh 拓扑审计：E01 存在124个蒙皮网格、10个含形态目标的网格；G01存在131个蒙皮网格、10个含形态目标的网格。按严格相同 SkeletonUUID + MaterialUUID + Attributes 分组，分别形成124/131个唯一组，**没有可直接合并的严格同签名网格**。因此绝不把这些网格粗暴合在一起；此前出现过骨骼扭曲、T型手、贴图消失的问题，不能重蹈覆辙。
