# R196｜GPU 恢复后的镜头、背景音乐与视觉事件安全接续

**日期：2026-11-19｜项目：《放学后决斗社》｜隔离 Draft / NO-GO**

## 本轮做了什么

承接 R195 的真实 GPU 上下文丢失后「只重建3D iframe，规则引擎仍在父页面存活」的机制。R196 解决三个直接影响玩家体验的缺口：

1. **重建体育馆时保持玩家手动设置的视角。** 父页面原本只更新画面上的角度文字，没有保存实际角度。现在它按同源子页面的真实 `ASDC_R48_CAMERA_ANGLE` 回执保存角度，并在恢复 URL 里记录到 `r196CameraYaw`。新的子页面只有在 R195 QA 恢复场景下才读取这个角度，并在**第一帧绘制之前**将 `orbitYaw` 和 `orbitTargetYaw` 初始化成相同角度。这样避免恢复后突然从默认正面镜头转回来。验证了 +90° 和 -90°；不改正常玩家相机默认值，不打开此前被禁止的自动特写。
2. **声音属于活着的父页面，不应被 3D iframe 故障强行重置。** R196 使用已有音频引擎对象；恢复前后保留 BGM 曲目、音量意愿、音乐历史，而不是重新调用 `setOpeningMusic` 或 `resetMatch`。确认第一次渲染故障后 **BGM 不重复选曲**。浏览器 `HTMLAudioElement.play()` 的兑现时间可能延迟，`musicStart` 计数偶尔在恢复后从 3 到 4、但曲目与历史不变；这是浏览器已有的待完成播放，单凭计数**不代表重播**。只记录、不因为这一正常异步行为锁住玩家。
3. **恢复是画面水化，不是重新出牌。** 重建后的首次 `ASDC_R45_BOARD` 用来呈现规则引擎现有单位（同样的 UID、HP、护盾和攻击状态），不得当成新单位进场而触发脉冲光效。只有第一次恢复棋盘同步跳过「新单位」脉冲，后续真实出牌仍照常反应。旧的法术受击、观众误伤不重放，避免结算发生第二次、声音再响一次。若玩家本来没听到开场广播，恢复时也不在中盘补播开场词。

**不更改正式玩家玩法**：R196 所有恢复状态只在 `qa=1&r189Stream=on&r190Demand=on&r195SceneRecovery=on` 时起作用。正式版 R147、GitHub main、源 VRM/GLB、骨骼/面部表情/服装材质、法术/物理互动与默认音量保持不变。16F 只在 Playwright 的测试请求拦截下运行，恢复时恢复原始 Three.js RGBA32F。

**数值不能误读：** 六次可计时的3D场景恢复记录约 **1901–1933ms**（Z890、头戴GPU真实Chrome、已有缓存，样本少；不是手机耗时、不是掉帧改善证明）。音频启动次数有可能因为浏览器自动播放异步兑现而变化，不能承诺语音口型音素级、配音音频精确进度的恢复；R196只确认音乐引擎未被重建、曲目/选择历史保留。

**未解决的偶发风险：** 更早的一次模拟手机430×900、+90° 场景在等待 `r195Recovery.state==='restored'` 时触发 **130000ms 超时**，且初步没有 JS/HTTP 错误。后续同配置与两次追加重复通过，但我们尚不能归因这次超时是GPU资源竞争、加载迟滞还是通信时序。保留为 NO-GO 的真实稳定性问题，不能将8次成功当作排除故障概率的证明。
