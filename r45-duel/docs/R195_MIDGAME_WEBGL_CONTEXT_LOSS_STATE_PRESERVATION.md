# R195｜真实对局中 GPU 上下文故障：不重置规则引擎的 3D 恢复

**2026-11-19｜放学后决斗社｜隔离性能分支｜Draft / NO-GO**

## 一、R194 的缺口与 R195 的选择

R194 已在真实 Chrome 中证明：被测试的 GPU 支持 RGBA16F 数组纹理与采样，且 QA 控制器能在真正的 `webglcontextlost` 事件后重新载入 RGBA32F。但是 **整页刷新会重建游戏引擎，导致当前牌局进度丢失**。

R195 使用更安全的隔离架构：

- **父页面 `game.mjs` 的真实 `g` 规则引擎不重建。** 全部卡组、双方手牌和生命、护盾、攻击加成、单位 UID、出牌事件、牌堆和弃牌顺序、AI 伪随机数状态保留在原父页面内存。
- **只重新创建发生故障的 `<iframe id="stadium">`**，浏览器本身不整页导航；新 WebGLRenderer 使用原始高精 VRM/GLB 与 Three.js 精度，重新加载真实模型，保留原始规则。
- 原始 R189/R190 流式加载依旧适用，区别是 **R195 恢复时的初始 GLB 清单来自此刻真实的双方手牌与战场**，而不是由 `createGame(seed, deck)` 算出来的旧开局手牌。父/子页面握手严格验证这批身份与实际源模型、seed、deck 一致。
- 回退时暂时禁用出牌；直到角色真正载入且场景同步、规则状态精确校验通过才解锁交互。恢复失败时禁止继续操作，不使用低模/假模型遮掩。
- **最多恢复两次。** 发生第三次真实上下文丢失时，进入 `failed` 安全状态，锁定出牌、不无限刷新。当前规则状态仍保持在父页面内存中，等待后续人工/产品层进一步处置。
- 精度变化在 R195 的**自动化浏览器里通过临时 Playwright 模块拦截产生**：初始 GPU 真的使用 R193 实验 `RGBA16F`；恢复 iframe 的请求不再拦截，使用存储在仓库里的未经修改的 `three.module.js`（真正 `RGBA32F`）。**正式玩家端没有启用半精度，`r195Force32f=on` 只是 QA 安全导航的明确标识，不是经过发布验证的全局开关**。

### 关键严格核验

以教室 seed6 为例，在第3回合出现故障：

- 故障前的完整规则状态指纹为 `c0d1f23b`（serial 9、round 3、JSON长度1885），恢复后相同；
- **实现不仅比较了指纹**，还在父页面内存中保留整个规则 JSON 作为私有快照，逐字节比较，防止哈希碰撞造成的误通过；
- 测试另对照手牌、HP、能量、事件记录、牌组、当前回合、当前战场，字段完全一致；
- 恢复后真实加载的模型包含当前需要的 `E02, M02, T02, E03, G02, T01`，并可能根据下一次AI行动提前按需加载其他真实原始GLB；
- 真正 `RGBA16F` 对战背景发生 Context Lost 后，实际 GPU 3D 纹理切换到 `RGBA32F`。本次教室场景 WebGL 浮点纹理 API 上传字节量 **30.472 → 65.617 MiB**，食堂场景 **46.987 → 93.975 MiB**（GPU 分配会随每次加载时的实际活动源模型数量变化，不能仅比较这两个数来推断精度和总显存）；
- 恢复后通过界面真实点击「结束回合」且 AI 作出回应，进入下一回合；不是单纯比较静态 JSON。

连续三次真实 GPU 上下文丢失的结果：

1. 第一次重新创建iframe，恢复为原始 32F、继续同一场比赛；
2. 第二次 iframe 同样重新创建，全部规则状态一致；
3. 第三次安全门槛拒绝再次刷新，`state='failed'`、`sceneReady=false`、`sceneError=true`，再次确认原始 `g` 完整未变，未形成无限循环。

## 四、R195 仍然 NO-GO

**R195 解决的是父页面仍活着时，子 iframe GPU context lost 后可重建画面、继续规则状态。不是全浏览器会话恢复。**

依然未验收：

1. **真实 Android GPU** 的 16F 兼容性、GPU丢失、OOM、温度/功耗、长时间多回合稳定性；
2. 浏览器页面崩溃、系统杀死 Chrome、断电/刷新后，父页面引擎内存也消失：本方案不能恢复，需要另立安全的持久化+完整性检查；
3. 重新加载后的视觉时间线、正在播放的配音、镜头角度和现场短暂特效的精确接续尚不保证；R195明确优先保证**规则与真实高精模型**，而非编造尚未确认的完整视听连续性；
4. 真正上线需把半精度策略变为受控、兼容保守的运行时功能，完成多设备测试和随时回滚，并审查性能开销；
5. 无法安全重建时目前是**失败锁定**，不是玩家端完善的恢复提示与继续按钮。

所以：**Draft / NO-GO，不改生产，不合并 main，不发布试用链接宣称已解决所有手机卡顿。**
