# R83 · 游戏声音默认开启（2026-11-12）

这次修改是产品默认行为，而不是开发调试开关。

## 玩家实际行为

- 首次进入：声音意图 \`requested=true\`，按钮显示「♫ 声音开启」，默认混音：音乐 44%、效果音 75%、人物语音 86%（延续既有个人音量设置）。
- 浏览器允许播放：页面载入时尝试并启动主题音乐；逐类预加载音效和已生成的 Qwen3-TTS 人物语音清单。
- 浏览器禁止直接自动播放：不弹提示、不遮住场馆、不要求先点声音按钮。首次正常触屏/点击手牌/键盘操作自动重试音乐并恢复音效与人物配音；被浏览器禁止的尝试不算资源损坏。
- 手动静音：声音按钮只承担关闭与恢复功能，明确点击「声音关闭」会保存 \`asdc_r83_sound_on=off\`；再次打开后仍尊重玩家自己的静音选择，点击「声音关闭」按钮可一键恢复。
- 游戏规则、人物状态、卡牌花费和场馆显示完全不因音频允许与否而改变。音频只作为表现层。
- 首次轻触前不保证每个受限制的浏览器都能出声，这是浏览器安全策略，任何纯网页都不应假称可以无手势强制绕过。

## QA

\`node r45-duel/qa/browser-r83-default-sound.mjs\`

生成 \`qa/evidence/r83/r83-default-sound-browser.json\` 与桌面/手机真机尺寸 Chrome 截图。三项测试：

1. 在 \`--autoplay-policy=user-gesture-required\` 下，**不按声音按钮**；第一次普通选牌后音效计数、背景音乐播放计数均应增加；出牌人物语音实际播放。
2. 同时验证宽屏和 430px 手机窄屏。主动静音，刷新后保持静音，再点击一次恢复。
3. 在 \`--autoplay-policy=no-user-gesture-required\` 下，**无需触摸**，载入后背景音乐就开始播放。

所有失败时均有实际浏览器错误输出；不把 CSS 的 aria-pressed 属性当成真正的出声证据。

## 更改范围

- \`audio-engine.mjs\`：明确区分声音意图 \`requested\` 与浏览器真正播放许可 \`enabled\`；加载时尝试并预解码，首次游戏操作重试被禁止的 HTML5 音乐；缓存待放的首张牌音效/语音，允许玩家主动关掉。
- \`game.mjs\`：捕获首个指针/键盘/点击来恢复声音；开局自动尝试播放、无需额外步骤；正常游戏交互照常触发音频。
- \`index.html\`：静态默认声音开启的界面基线；后续按照真实本地静音意图同步按钮。

正式上线边界：此更改推送到 R82 实验分支并纳入既有 PR，尚不假称已合并或发布公网。
