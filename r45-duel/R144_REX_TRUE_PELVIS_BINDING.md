# R144 Rex：原始高精 GLB 真正加权的骨盆、全身传动与动作回归

**基线：唯一 main 的 R143（`9fddbb8`）。此阶段不改变普通玩家 R97，也不替换其他角色。**

## 问题证明：原始骨盆节点存在，但不是有效绑定

从原始授权 Blender Studio `rex.blend`（约 85MB）以 Blender 5.2.3 LTS `--disable-autoexec` 只读审计，确认原 CloudRig 1556 个骨骼、28 个有手臂变形约束的 GEO 网格、38036 个源顶点。作者的 `DEF-Hips` 由 `CTR-DEF-Hips` 控制，**没有下级变形骨骼**，虽然一个原始顶点保存了几乎为零的权重，但没有可被实际驱动的骨盆网格。作者输出的 R132 BakedRest GLB 中，该关节存在于 skin joints，但有 **0 个直接蒙皮顶点**。旧 R142 正确删除了对它无效的第17条动画轨。

原始 R132 是 `T04-Rex-Skinned-R132-BakedRest-PILOT.glb`，SHA-256：

`fabe89345185d8b07c21cee058ee4f0488b164b342525a295084809f4c045179`

## 原源骨骼的传动与动画

`scene/r144-rex-real-pelvis.mjs` 保留 R143 已修复的脊椎→胸→头→肩链和 R128 原腿部层级。现在把**真正有权重的原 `DEF-Hips`**接成 `DEF-Spine` 和左右 `DEF-Thigh1` 的父级，使用 `Object3D.attach` 保持原世界绑定姿态；验证加权网格绑定前后没有可见位移。

以原始七段 R135 动作的同一时间轴，为原 `DEF-Hips` 添加真正的第17条动画轨：待机、攻击、挨打、走动、威胁、防御紧张与庆祝分别有不同的骨盆俯仰和侧向承重。不会把其他角色连带改为通用木偶晃动。

新旧切换：

- `?r135Pair=on&r144Rex=on`：T04 使用新高精有权骨盆，仅实验高精角色。
- `?r135Pair=on&r144Rex=off`：回到旧版 R132 T04，16条旧源轨。
- 不带角色实验参数仍是 **R97** 正式原资产。R143 的 `?r143Rig=off` 是另一个独立层级回退开关。

## 实际 GPU 初轮：152/152

Z890 RTX + Chrome Vulkan，桌面 1440px、竖屏 430px，对原 R132 与新 R144 做同一场地的待机、攻击、挨打和庆祝测试。实际 QA `qa/browser-r144-rex-true-weighted-pelvis.mjs` 结果：

- **152/152 项通过**，全部来源是同一真实高精蒙皮角色。
- 原模型 16 条源轨且骨盆加权顶点 0；新模型 **17 条有效源轨、4953个强绑定顶点**。
- 真正原骨盆旋转峰值：桌面 `0.09724`、竖屏 `0.09788` 弧度。
- 新骨盆绑定网格的加权顶点真实位移峰值：桌面 `0.01461`、竖屏 `0.01469` 场景单位。
- 双视口原鞋底接地穿透均为零；原脊柱、手臂、膝盖、脚趾、表情继续正常。
- 老模型和新模型的真实体育馆镜头对照截图均已生成并保存于 `qa/evidence/r144/rex-pelvis/`。

**限制：**新骨盆绑定虽然解决了数据和运动链缺陷，但实际默认远景下肉眼差别仍然较小；这不能算导演对表演的 85/100 审美签收。下一步仍需真正改进全身夸张动作、镜头近景和反应节奏，而非继续滥加空动画。
