# R142 原著高精角色：Rex 防守重心与 Jay 实验跨步

基线：唯一正式游戏 GitHub `main` R141，提交 `23138dc`。角色仍使用 Blender Studio 原始带蒙皮 GLB 和现有角色动作调度，不造方块替身、不改卡牌规则、不冒充公网部署。

## 用户可见的动作问题

此前 R135 实机报告 T04 Rex 的真实加权腿部顶点移动峰值只有约 `0.0177` 个场景单位，远景容易出现“上半身拦门、腿像木棍”。G03 Jay 已有约 `0.050` 的动作，但施法和失败反应的下身节奏不够分明。本轮修正人体真实关节而不靠整体根节点摆动冒充动作。

## 两套不同的源骨动画

Rex：
- 取 `T04-Rex-Skinned-R132-BakedRest-PILOT.glb` 原始左右大腿、膝、脚、趾关节，保持原 GLB 及真实皮肤权重。严格复查发现该源文件虽存在 `DEF-Hips` 骨骼名，但它没有直接绑定顶点，也没有子骨骼；此前加入的骨盆轨属于**无效动画**，R142 已将其删除。
- 以两腿宽支撑、预备下沉、沉重封堵、受击屈膝退步和恢复站稳为动作结构。仍为 **8 条上身 + 8 条真实腿骨轨 = 16 条有效源轨**；不存在所谓第 17 条有效骨盆轨道。
- 与 E03 活泼加油队长的轻盈蹦跳刻意区分；Rex 不继承其 `getLift()` 空中跳跃。

Jay：
- 取 `G03-Jay-Skinned-R132-BakedRest-PILOT.glb` 原始左右大腿、膝、足、趾。原 GLB **没有 `DEF-Hips`**，所以禁止凭空创建 Jay 骨盆。
- 按实验员的短促准备跨步、探身施法、实验失手后撤、谨慎复位设置非对称五拍原骨骼动作，仍保持 8 上身 + 8 真腿 = 16 条源轨。

## 代码与接地约束

- `scene/r128-source-lower-body.mjs`：新增 `r142Rex` / `r142Jay` 的专属下身关键帧；对失效的 Rex `DEF-Hips` 轨道做证据驱动的撤销。
- `scene/summon-models.mjs`：仅在 `r135Pair=on` 的 T04、`r134Jay=on` 的 G03 启用；无参数正式 R97、其他演员不变。
- `scene/r133-source-shoe-contact.mjs`：基于两只**实际加权原鞋底 SkinnedMesh** 检测世界最低点，分角色有界补偿。T04 因真实骨盆拦截动作需更大运动空间，上限从 0.082 调整到 0.105；E03/G03 均仍为 0.082。每帧根据实际鞋底重算，不累加上浮。不得用无限提高上限掩盖穿地。
- R135 原既有浏览器 QA 仍然严格要求 16 条有效原始骨骼轨道；R142 的新专项额外核实大腿样本确实有真实来源顶点权重，不容无效骨骼虚报。

## R142 独立 GPU 镜头检查

`qa/browser-r142-original-guard-lab.mjs` 在 Z890 RTX + Chrome Vulkan、桌面 1440px 和竖屏 430px 的正式体育馆镜头，按两角色×待机、攻击、受击、庆祝依次触发，检查对手朝向、真实带权重腿部位移、鞋底不穿地、源轨道数和 GPU 资源无错。

最终 R142 专项实际结果：T04 桌面真腿顶点约 `0.03285`（基线 `0.0177`），G03 约 `0.07898`（基线约 `0.050`），双视口 **86/86** 通过、两人两视口鞋底穿地均为 `0`、轨道均为有效原始 `16` 条。严格检查已证明 Rex 的原始 `DEF-Hips` 无直接蒙皮权重且无子骨骼，故移除该无效轨；测试改核验原大腿/膝/足的真实顶点权重。旧 R135 竖屏一度因接地上限不足偶发失败，在调整 T04 的实际原鞋底有界接地后，R135 双角色正式源演出 53/53 与 R134 Jay 22/22 重新通过，其他历史回归继续执行。
