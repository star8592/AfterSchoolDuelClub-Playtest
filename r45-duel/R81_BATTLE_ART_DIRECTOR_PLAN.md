# R81 全三维卡牌决斗 · 真实命中、人物演出、配音、比分牌与座椅统一制作总纲
日期：2026-11-12；项目：`star8592/AfterSchoolDuelClub-Playtest`；隔离工作分支 `feature/duel-r81-impact-audio-score-seats-20261112`。

## 总判断

所有表现必须服从真实卡牌规则。每次“打出牌 → 出牌者抬手亮牌/喊招 → 技能运动到目标 → 实体目标有受击/躲闪/格挡 → 人气/护盾/伤害数值按规则更新 → 双方恢复站位 → 能继续操作”构成完整闭环。不能让演出虚构命中、死亡、胜负或伤害。角色是动画电影风格人物，不是统一魔法师：每人有个性动作、专业领域特色、声音、音效、技能轮廓。美术角色原画/比例/骨骼与声音身份一致，不能用光圈掩盖低模/反向/穿模。

## 已完成的 R81 独立开发实现

- `scene/spell-impact.mjs`：6 种以具体卡为单位的原创视觉攻击/辅助：E06 **巨型黑板擦实体飞来、砸地并产生震荡冲击**；T06 **多层广播音浪与线束**；G05 **修补晶体上升**；G06 **漂浮书页和符纹**；T05 **暖汤金色光潮**；E05 **加油能量脉冲**；不同形态不再都是同一颜色光圈。
- `scene/scene.mjs`：`ASDC_R81_SPELL_RESULT` 从游戏真实战斗回执触发命中特效；`ASDC_R46_CARD_PLAY` 同时驱动两侧真人型决斗者 **出牌/抬臂/俯身/恢复**，受到实际伤害可出现 **后仰和护身动作**；保留 R79 三维召唤门与已有高精度 3D 角色和战斗逻辑。
- `scene/summon-presence.mjs`：按实际受击 UID 触发当前存活目标的 hit 动画/位移反冲；已被规则引擎移除的死亡对象不虚构存在。旧版攻击与连击序列仍保留。
- `scene/live-scoreboard.mjs`：体育馆内 **真实3D LED分数屏**，从引擎只读地获得左右人气 HP（0–20）、回合、两队连携数；受到真实伤害时数字高亮。现有网页 HUD 同步放大数字，强调 `HP` 并非伪造比赛积分。
- `scene/real-stadium-seats.mjs`：用带软圆角坐面、桶形背靠、双扶手、金属支撑与拼色坐垫的完整分件座椅替换无靠背的小色块，共 **396 个椅位：前排198，反向198**；每类零件用 `THREE.InstancedMesh` 实例化，画质和 Draw Call 兼顾。人工美术近景审查仍未完成。
- `audio-engine.mjs` 与 `assets/audio`：继承 16 条现有 Qwen3 语音，新增左右出牌者各2条中文配音与其余缺失的12条召唤人物入场/攻击语音；**当前实得32条：14名召唤人物各2条=28，左右出牌者各2条=4**；新增8类原创合成音效。人物每项需人工试听，浏览器音频必须经“开启声音”用户点击解锁。
- `game.mjs`：`playerHP`、`aiHP`、`comboCounts`、`round` 从权威状态推送到场馆显示器；`E06` 等法术效果来源于实际 `playCard` 返回后的 HP/UID 差值，**不自己结算伤害**；`endTurn/aiTurn` 实际造成的人气损失驱动对手反应和记分牌高亮。
- **限制**：R81 当前为开发版，不宣称全角色动作美术、体感、阵容 AI 平衡或正式发版完成。

## 声音制作与人物台词流程

- **人物**：每张召唤卡至少 `enter`（辨识身份）和 `attack`（真实攻击），重要角色后续追加 `hit`、`shield`、`special`、`win`；左右出牌主持者分别有 `cast`、`hurt`、`win`、`lose` 等。台词长短与动作/镜头匹配，不要每回合机械重复一整段话。
- **出牌**：纸牌摩擦/亮牌啪响 → 蓄力嗡鸣 → 物体真正撞击的重低音、碎裂/扬尘 → 人物受击吸气/喊痛 → 分数变化的短提示音；跳过技能动画不得重复结算。
- **赛事**：开赛提示、回合切换、场馆空间混响、观众细小反应、比分变化、关键反击、胜利观众欢呼。观众声不宜每次技能都过量。
- **语音品质**：本地 `Qwen3-TTS` 原创人物声线→试听筛选→情绪/发音修正→样本文件 SHA+manifest→和面部表情、口型/肩臂姿态同步；模型生成不是音色美术批准。不同角色不能全部使用同一个冷漠播报腔。
- **音量**：保持音乐/音效/人声三路混音；强打击瞬间音效可暂时压低音乐，主语音优先级高于背景，人声不能排队遮挡关键下一回合操作。浏览器按明确用户手势解锁声音，支持静音，避免默认自动响。
- **本轮真实生成**：8 个原创短音效的来源与 SHA 在 `assets/audio/r81-audio-provenance.json`，配音原始台词/说话人登记在 `qa/r70-qwen3-voice-lines.json`，实际音频清单在 `assets/audio/voice-manifest.json`。已通过32条文件的存在性、sha256、Ogg/Opus及时长校验；角色表演/音质仍须逐条人工听审，不能把生成成功写成最终审美批准。

## 体育馆、比分、观众和摄影规则

- 主人气对应游戏规则 `g.hp[player/ai]`、每方最大20；中心为回合状态，次要为真实 `comboCounts` 连携数；不要凭空创造竞技场分数或击杀数。
- 3D LED 电子比分牌位置在看台前方的原主招牌位置，必须从比赛主视角能读到；网页固定HUD保证手机屏幕能辨识数值。双方受击数字高亮与音效同步，不频繁乱跳。
- 座椅应有真正靠背、坐面、支撑和扶手；前后主看台396个实体座位，面向球场，坐面合理高于台阶。颜色错落但不应呈平面棋盘；InstancedMesh 降低drawCalls。
- 默认摄影是人眼高度，不剧烈抖动，重要命中只有很短受控冲击和视觉停顿；近景镜头必须同时看清施法者和受击者，不能让大特效挡住双方 HP。
- 不造假观众：如果没有合法高品质观众模型，就先保留真实空座椅，观众音效优先小心使用；以后用 InstancedMesh+3–5种高质量看客的可控动画填充，不用卡通方块代替人物。

## 必须持续验收的实际路径

1. **真实玩家技能**：在 R81 真实游戏里用 seed=5，先结束第1回合，第二回合打 E06；20→17，玩家出牌 / 巨型黑板擦 / AI受击 / 分数变化同时发生，人物出牌势与音频关联。
2. **真实召唤**：seed=1 正式出 E01；手牌5→4、真实 `card_play` 事件、三维门户和持续在场的召唤实体；不能只是 VFX 页面播放。
3. **场馆**：`R81_Real_Time_Stadium_Jumbotron` 真实mesh；396 个实例化实体座椅（前198/后198），而不是旧矩形 markers。
4. **声效**：授权点击“开启声音”后，通过 Qwen3 Ogg 与 WebAudio 原创SFX，查询`audio.status()`真正播放成功、无解码与HTTP异常；发音人工试听另计。
5. **反例**：如果法术不会造成实际伤害，则不可触发受害者命中台词/扣血；音量关闭不影响规则，跳过演出不重复伤害。
6. **跨设备**：Chrome GPU真实截图/录像，S22、现代平板性能和不同屏幕横竖排版；记录 drawCalls、p95、纹理/资源响应，至少一次人工实看与听声音。
7. **商业发行**：严格在隔离分支通过美术、性能、测试后才合入/上线，线上和其他隔离R78/R80工作区不被擅自覆盖。原生合成的 VFX/音效无需因第三方许可追查而停工。
