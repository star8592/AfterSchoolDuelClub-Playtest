# R115 · 不降人物精度的 3D 首次加载压缩（2026-11-13）

## 问题与解决方式

R114 已改进加载调度和正式开场画面，但实际公网冷访仍需约 17.46s 才进入首帧。主要瓶颈是一次性读取 16 个 VRM / GLB（4 位 VRM + 12 个真实召唤模型）。本轮不改变 16/16 的真实角色验证门槛，不用低多边形替身，不删除表情、骨骼和动作。

**纯数据优化，保留所有原网格/骨骼/动画和可见贴图的原始像素：**

1. `scripts/r115-lossless-webp-glb.py` 使用 Pillow WebP `lossless=True,exact=True` 替换实际 PNG 贴图，仅在节省 >=1% 时生效；转换前后每张都以 RGBA 解码逐像素比较。使用 glTF 官方 `EXT_texture_webp` 扩展，不转换 JPEG，也不改材质、网格或动作。8 个模型、132 张贴图改变格式。
2. `scripts/r115-meshopt-glb.mjs` 使用开源 Meshoptimizer 1.1.1，按 glTF accessor 数据步长无损压缩 1,932 个二进制 bufferView；**每一个压缩缓冲都被立即解码并与原始字节逐字节比较**。使用 glTF 官方 `EXT_meshopt_compression` 必需扩展和无实际资源内容的规范 fallback 缓冲。顶点位置、权重、索引、骨架、动画等的值/顺序都不改变，未进行量化。
3. 集成 29KB MeshoptDecoder（可加载 ES Module）到运行时及角色检视工具，浏览器可直接解析新资源，无第三方运行时 API 依赖。构建用 Encoder 和运行时 Decoder 均来自 `meshoptimizer@1.1.1`，MIT 版权声明分别保存于 vendored 目录。
4. 旧的高品质 PNG/顶点原文件仍可从主线压缩前 Git 历史恢复；未在正式网站额外保留 152 MiB 的重复旧文件。

## 兼容性边界与回退

- 使用本项目已内置的 Three.js GLTFLoader 对 `EXT_texture_webp` 和 `EXT_meshopt_compression` 的支持。仅改造真实使用这批资产的运行时和旧角色检视页。新压缩文件要求加载器设置 `MeshoptDecoder`；无法运行 WebAssembly 的特殊浏览器可能需要回退至先前的 Git 提交，而非伪装成已加载。
- `scripts/r115-lossless-webp-glb.py` / `.mjs` 两步的 **apply 仅用于未经优化的源资源**；先运行 Pillow 阶段，后运行 Meshopt 阶段。若重新构建应从开工前的资源提交恢复源文件，而非对已优化文件重复执行。两个脚本缺少 `--apply` 时不覆写源文件。
- 旧文件保留在 Git 历史，回退时一起恢复模型、JS 解码器引用及相应网页，不允许只回退其中一部分。生产网站以 Pages 实际发布成功和公网 Chrome 验收为准。
