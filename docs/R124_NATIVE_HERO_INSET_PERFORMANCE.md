# R124 · 原生人物特写渲染减负、可读表情与同局整链路验收

日期：2026-11-13。基于 GitHub main `921a610`（已含 #111、#113、#114、#115），**R122 #109 / R123 #112 仍是独立未合并分支**，没有偷换其素材或合并状态。

## 症状与根因

R121 主竞技场先 `renderer.render(scene,camera)`，然后英雄特写用另一个 `PerspectiveCamera` 再对同一完整体育馆场景调用一次 `renderer.render(scene,heroCamera)`。即使 inset 面积小，第二次依旧遍历与绘制全场可见对象及灯光阴影。真实 K01 出牌链、桌面/430px 竖屏 GPU Chrome，画面功能通过，但连续战斗出现 33 ms 级帧间隔。

另一个独立美术问题：原镜头距演员较远、略俯拍，舞台 inset 基本出现人物全身，眼神/情绪不显著。人工看过实体截图后确认，过度偏向主摄像机的三分之四角度会让举起的实体卡牌盖住脸，因此实际特写应优先看**源 VRM 真正面部**，卡面仍由不中断的主镜头显示。

## 实施

- 主镜头保持 layer 0，完整体育馆、看台、所有召唤物不改变。
- 两位源高精 VRM 及其真实手中卡牌分别额外开启 player layer 1 / AI layer 2，**保留原 layer 0**；所有源骨骼、表情 morph 与 15 手指关节保持原件，不新增替身或面部贴画。
- inset 根据当前角色选择其专属 layer，只重绘对应本人、原手牌与灯光，不重绘整座体育馆。镜头、原场馆和同一 GPU canvas 不变。
- 第二次小窗口渲染暂时禁止 `shadowMap.autoUpdate`，复用主画面已更新的阴影贴图；使用 `try/finally` 立即恢复渲染器状态。
- 近景调整到对手视线侧、近眼高的胸部以上取景，显著缩小原来全身/小脸问题。手机和桌面继续独立 inset 尺寸，不遮比分或底部手牌。**人工截图复核优先表情，不以卡牌遮面换取“同时看到大卡面”。**

## 核验记录（Z890 RTX 5070 Ti，Chrome Vulkan，真实规则 K01；不同 run 会有 GPU 噪声）

| 版本 | 桌面 P95 帧间隔 | 桌面 >33.3ms 帧 | 竖屏 >33.3ms 帧 | 峰值 drawcalls |
|---|---:|---:|---:|---:|
| 原 main `921a610` | 33.4ms | 20 | 9 | 1211 |
| 角色专属渲染层初次修复 `12ade12` | 16.8ms | 8 | 4 | 835 |
| 胸像取景初次复测 `bde6bd1` | 33.3ms | 10 | 3 | 835 |
| 试验卡画朝向 `a475363`（已撤销该镜位） | 33.3ms | 10 | 4 | 835 |

以上为单次短时间样本，不是保证任何设备均达到 60FPS，P95 波动需承认；最可重复的性能收益是同一规则命中演出的 render drawcalls 从 1211 降至 835（降低 31.0%）。原有 scene 内模型仍 16/16 真实加载。本机 2.2–2.8 秒首帧就绪属于已缓存、本地服务器条件，不能外推到公网冷缓存。

新自动化测试 `r45-duel/qa/browser-r124-full-chain-benchmark.mjs` 对同一局真实卡牌 K01 同时断言：规则扣血仅一次、15 元素场景、真实角色被击、原生手指实际抓握、近景发生、真实卡画缓存、原配音触发、零游戏额外修改，并分别采样桌面/竖屏的 idle 与 combat requestAnimationFrame 间隔。设置 1050 drawcall 回归预算，防止重新引入重复体育馆渲染。

测试回归：
- R124 全链路：18/18 PASS（桌面+430px）。
- R121 原 VRM 表情/特写：42/42 PASS。
- R121 真实五指握牌：24/24 PASS。
- R121 真规则命中：14/14 PASS。
- R121 元素映射：46 spells / 32 motifs / 15 elements / 46 signatures PASS。
