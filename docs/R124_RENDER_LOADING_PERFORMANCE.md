# R124 游戏加载和战斗特写性能专项

## 审计对象及真正瓶颈

2026-11-13，正式主线 main 在 Z890 Chrome / RTX 5070 Ti 检查。正常首次完整加载约 94.6 MB、静止竞技场约 616 draw calls；4 倍 CPU 降速后，普通场景每帧间隔大致 33.3ms（接近 30FPS）。这不能直接代表用户手机的实际 FPS，但说明低算力端确实存在卡顿风险。

R121 的英雄镜头以前直接用第二台摄像机**再次绘制整个体育馆**。通过同版 `?r124Quality=legacy` 回退对照，在举牌施法时：

| 指标 | 旧实现 | R124 优化 | 事实 |
| --- | ---: | ---: | --- |
| 桌面整体 draw calls/帧 | 1164 | 787 | 降低 32.4% |
| 竖屏整体 draw calls/帧 | 1162 | 787 | 降低 32.3% |
| 竖屏第二镜头 draw calls | 503 | 128 | 只绘制该人物真实 VRM |
| 竖屏像素比 (DPR 2.5 输入) | 1.5 | 1.2 | 片元着色像素下降约 36% |
| 竖屏动态阴影分辨率 | 2048×2048 | 1024×1024 | 阴影画面不是关掉 |

原有两侧高精度 VRM、骨骼、表情、腕部 3D 卡牌、真实竞技场、用户旋转和音效完整保留。分离摄像机可见图层，特写镜头只渲染当前角色以及真实三维灯光；常规镜头仍渲染整座体育馆。阴影缓存只按 20Hz（待机）/30Hz（战斗）刷新，以减少重复阴影通道。桌面原分辨率和 2048 级阴影不变。

在同一 Z890 Chrome、4 倍 CPU 降速、430px 竖屏/DPR 2.5 的**1.7 秒真实特写段**中，旧版采到 28 帧，新版 37 帧；帧间隔超过 50ms 的次数由 12 次降至 4 次。两者中位帧间隔均接近 50ms，不能据此宣称已稳定达到 60FPS，也不能把它当成真实手机 FPS。

## 不改变人物文件的 12 GLB 无损传输优化

所有原始 GLB 原封不动保留；生成另外 12 个默认启动资源的确定性 gzip wire copies。它们不修改网格、动画、shader、材质、纹理和资产授权信息，逐字节解压 SHA-256 验收。

| 项目 | 原 GLB | 压缩 `.glb.gz` |
| --- | ---: | ---: |
| 12 个启动 GLB | 56.31 MiB | 42.82 MiB |
| 真实 Chrome 该页全部资源传输 | 90.23 MiB | 76.75 MiB |
| 模型通过加载 | 16/16 | 16/16 |

浏览器实际使用 Fetch + 原生 DecompressionStream，无该 API 的旧浏览器仍加载原始 `.glb`。此外支持 `?r124Packed=off` 手动禁用压缩，网络/CDN 自动解压会通过响应真实 magic bytes 检测避免重复解压。进度只报告真实收到的字节；遇到文件不存在或格式无效明确报错，绝不拿空场景冒充加载成功。

**注意**：高速本机测试因增加本地解压，压缩模式并不一定更快（本地一次观测约 2.64 秒 vs 2.32 秒）。这一优化的主要收益是网络受限设备的传输量，非对所有环境承诺耗时减少。

## 回退、验收及限制

测试回退链接参数：`?r124Quality=legacy&r124Packed=off`。这会重新使用完整 3D 次镜头、原始阴影更新、原始像素比和 GLB 传输，便于故障对照。正式质量方案自动判定高 DPI 竖屏端，不暴露与玩法无关的复杂设置给普通玩家。

已执行测试：

- `node r45-duel/qa/check-r124-packed-assets.mjs`：12 模型逐字节原始文件身份校验。
- `node r45-duel/qa/browser-r124-packed-download.mjs`：真实 GPU Chrome 两种加载模式、16/16、9 项检查。
- `node r45-duel/qa/browser-r124-hero-budget.mjs`：真实 GPU Chrome 两种摄像机管线、桌面/竖屏，20 项检查。
- `node r45-duel/qa/browser-r121-emotive-cinema.mjs`：原 3D 真人形象、表情、正面举牌特写，42 项通过。

正式上线以主线 PR 合并和公网 Chrome 真实回执为准。该报告不声称解决了全局数百 draw calls 的全部问题；若要继续改善低端手机还需长期跟踪 WebGL 角色 draw-call 批处理、粒子超额和模型首屏按需加载。
