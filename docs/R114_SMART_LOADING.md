# R114 · 智能加载与正式开场画面（2026-11-13）

## 目标及边界

- 保持《放学后决斗社》唯一正式 r45-duel/ 入口和原有玩法、魔法、角色骨架不变。
- 三维加载不再按「双核心 VRM → 双主持人 VRM → 12 召唤 GLB」三个网络批次串行等待。
- 优先 4 个 VRM，并与有界 GLB 队列并行。省流量/2G 模式为 2 个同时加载，触摸设备为 3，桌面为 4。所有 16 份真实模型仍需完全下载、解码和通过原始模型检验才能开始对战；不使用低模代替，也不伪造百分比。
- 首屏仅用 HTML/CSS，未添加图片、字体或第三方请求；正式标题、竞技场开幕灯光、已验证的模型进度、简洁规则提示和可访问错误重试按钮。
- 首帧合成留白保护：自动化/qa 模式仍以 >=850ms 且 >=7 帧为准；普通玩家为 >=320ms 且 >=7 帧。此处对 Headless 的旧截图回归边界保守处理。
- `window.__ASDC_LOAD_METRICS` 暴露本地模型验证耗时、首帧解锁耗时和已验证数量供性能测量，不上传遥测。

## 独立端口的本机真实 Chrome QA

测试版本：GitHub `origin/main` 7b03758 上的 R114 分支。服务明确指向本工作树，在 127.0.0.1:17351 验证。最初 11114 端口已有旧进程，后来排除，旧页面不计入结果。

- `browser-r114-smart-loader.mjs`：桌面 1440px 与手机 430px，均验证正式画面存在、真 16/16 资源、2 个主角与 12 个独立召唤模型、首帧解锁、按键启用、零 JS 错误。**通过**。
- 首次本机浏览器实测：桌面 2,959 ms（模型完成 1,728 ms，首帧 2,587 ms）；手机视口 2,728 ms（模型完成 1,738 ms，首帧 2,597 ms）。受本机磁盘缓存、环回 HTTP、硬件 GPU 影响，不等同于公网首访，也不能单凭这些数据断言相较 R113 加速了多少百分比。
- `browser-r96-recovery.mjs`：桌面/手机故障注入、禁止出牌、重试后恢复，14 项通过。
- `browser-r111-real-duel.mjs`：桌面/手机魔法、真实召唤、卡组切换不重下 16 个模型、GPU 清理，28 项通过。
