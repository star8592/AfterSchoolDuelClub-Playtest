# R121 · 真实 VRM 表情形变 + 举牌人物 3D 近景

## 创作问题
此前 R120 发牌手腕虽然大幅抬高，整个体育馆正面主镜头仍让左右主角显得很小；高举的大号卡画一旦和头重叠，玩家看不到表情反应。胜利与失败的原脸部 morph 也缺少差异。

## 美术原则
- 两个发牌主角继续使用原 Host-HairSample_* CC0 高精 VRM；
- 保留原高精实体卡牌和主画面完整构图的独立近景镜头由与大体育馆相同的 THREE.Scene、同一真实对象和另一 THREE.PerspectiveCamera 完成，绝不采用图片人物代用品；
- 在真实亮牌事件和胜利结算的有限时间片内用 WebGL scissor/viewport 渲染右上/左上的真实人物近景，站在原对手视线方向拍摄主角真实脸部，并保持主画面上全部人站着面对对手，玩家手动旋转镜头不被打断；
- 支持桌面和手机不同 inset 尺寸，避开上方比分 HUD 和底部真实卡牌按钮；支持系统减少动态效果；
- 手腕出牌位置为站在真实对手对面的姿势，卡画不再强遮演员脸部；进一步减小牌面的物理尺寸由另一 R121 手指分支处理；
- 采用与双方队伍区分的金色/蓝色影框，上方显示简短角色特写标签。专业级自动检查应该包括角色头骨真实投影在 inset 摄像机视锥内，原来源 face morph 真实生效，低于性能 drawcall 预算。

## VRM 作者源面部能力
解码两份原始 VRM0 glTF 的 blendShapeMaster：
两名主角均拥有 Blink、Joy、Fun、Angry、Sorrow 和 Surprised（以及 A/E/I/O/U 口型）。
在 vrm-character-acting.mjs 中统一管理真实脸部 BlendShape 权重：
- 举牌：Surprised
- 女生发动/获胜：Joy
- 男生发动：Angry
- 真正受击：Surprised
- 真正输了：Sorrow
- 情绪反转：先把所有托管 Morph 还原再施加本帧权重，不让“哭脸+笑脸”残留在同一张脸上。
双方源骨骼、面部都是独立实例，卡牌伤害/胜者仍只由真实 core 管。

## 验收
qa/browser-r121-emotive-cinema.mjs 在 GPU Chrome 桌面+竖屏 42 项检查：
两份实际原脸模型存在愤怒、悲伤；近景只在真实举牌或胜负事件出现；真正人脸处于画面之内；不压住比分和操作 HUD；获胜与失败 2 人的原 morph 实际取得显著大于零的权重；drawcall 预算 <1300；不修改权威 game board。
注意：通过视觉/技术测试也不等于每个脸部截图都达到最终电影感，仍应检查真人脸和牌画是否互相遮挡，必要时调物理卡牌比例和右手腕位置。
