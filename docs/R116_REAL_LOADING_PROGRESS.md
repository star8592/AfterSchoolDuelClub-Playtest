# R116 · 真实字节进度、慢网络恢复与队列 A/B（2026-11-13）

## 用户体验变更

- **真实下载数据：** 使用本地 `GLTFLoader.loadAsync(url,onProgress)` 的进度事件，汇总 4 位 VRM 主体和 12 个当前实际加载的 GLB 文件的 `event.loaded`，显示“已接收 XX.X MiB 模型数据”。这是浏览器交付给加载器的**模型响应体字节**，不是 CDN 网络计费流量，也不是臆造百分比；缓存命中时也可能显示已接收的资源数据。不同于 16/16 真实模型*验证*进度。
- **不假装加载完成：** 在 `verifiedModelLoaded` 模型骨骼/包围盒等原有检查完成前，不增加验证数量；在首帧渲染就绪前，仍禁止战斗。
- **慢网络救援：** 12 秒仍未就绪时显示“连接较慢，正在继续准备真实人物”和可选的“重新加载场景”按钮。正常加载继续进行；用户自行决定是否重试。资源加载真的失败时清除超时提示，保留原有错误/重试说明。
- 只有验证进度栏用于 16/16；下载数据量仅作文字提示，避免“下载完了就假装能够召唤”。加载期间不引入插画、额外字体、外部网络或遥测。
- 为避免频繁 DOM 更新，真实下载量在下一浏览器动画帧更新，保证每批事件最终会被绘制，避免仅靠固定节流遗漏最后一次传输进度。

## R115 当前资产背景

- 压缩后 16 个清单模型约 **84.997 MiB**。实际默认运行版本可能加载不同的 R60 纸飞机模型，所以 R116 浏览器实测“已接收”约 **85.6 MiB**；两组统计口径不同。没有篡改 16 个真实模型的验证、文件大小、网格、表情与动画。

## 公网性能 A/B：角色加载顺序

在同一 Z890 / Chrome / GitHub Pages 环境，4 次独立浏览器上下文用**仅限测试页**的路由替换，比较旧 `UNIT_MODEL_IDS` 顺序与“按文件大小从大到小启动”，GLB 并发仍为 4，均需 16/16 完成。

| 顺序 | 模型验证就绪 | 首帧就绪 | 结果 |
|---|---:|---:|---|
| 默认，第 1 次 | 11,851ms | 12,705ms | PASS |
| 大文件优先，第 1 次 | 12,799ms | 13,663ms | PASS，变慢 |
| 大文件优先，第 2 次 | 10,682ms | 11,537ms | PASS，变快 |
| 默认，第 2 次 | 11,959ms | 12,817ms | PASS |

**结论：** 并没有获得一致、可证明的加载时间收益，本轮继续使用已有并发 4 和原始队列。只据此发布“字节进度 + 慢网反馈”，不承诺降低公网首次加载的秒数。R115 4/6/8 并发 A/B 仍有效，不盲目提高请求数量。
