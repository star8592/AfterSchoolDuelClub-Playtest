# R41 现有三维召唤物动作与战斗镜头（独立试玩）

R41 在已通过公网验证的 R40 基础上复制，**不修改 R40、R39、R38、R25 或 PlayMoru 正式站**。

本轮仅增强已有资源，完全暂停音乐老师研发：

- **3D 动作线**：E02 纸飞机与 T02 菜单怪物仍使用既有 GLB，不生成新人。直接读取真实 `core.mjs` 交锋中的攻击者/受击者 ID 和单位 UID，驱动三维模型的短距离前冲、倾斜、后坐与回位；若单位或战线不匹配则不冒充动作发生。体积整体变换是**真实 3D 网格动画**，但不等于新制作了骨骼格斗。
- **镜头与可用性线**：在战场顶部添加“镜头：全景/近景”、上一招回看与最近交锋摘要。相机使用平滑正交缩放，手机端限制缩放以免裁掉两人。普通卡仍保留 R40 的真实规则伤害/格挡/反击动画。
- **资源一致性**：本版战场直接加载经过库内锁定的 `src/card-model-stage-r23.mjs`，通过本仓库 Three.js vendor import map 解析，避免只修改原始模块却仍加载过时的打包产物。
- **不变**：18 张卡牌原核心规则逐字节保留；E01/G01 的 R14 骨骼双人对决保持原样；E02/T02 原 GLB 保持原样，其他角色不冒充 3D 完成。

## 放行条件

1. 浏览器能正常解析 ES Modules、无 404/JS 报错，实际 E02/T02 GLB 加载成功。
2. 固定真实对局出牌并产生 `exchange` 后，可核查 `qaR41=1&qaR23=1` 的三维动作帧与事件序列，角色模型必须实际发生空间位移。
3. 全景/近景切换有效，回看战斗不会再次结算伤害或改变血量、回合、能量。
4. 桌面与手机分别检查布局；**仅当真实 GPU 渲染器被识别时才能声称 GPU 实机验收**。SwiftShader 只允许用于功能性排错，不作为性能验收。
5. 必须独立公网 Pages HTTP 200、旧版地址仍可使用，才可称独立 Demo 发布成功。
